The reward functions

3 arms

Every arm scores the same six outcomes and differs only in what it pays for them. The outcome is decided once, in outcome_for; the arm is a lookup table over the result.

no_answernothing written, or the scorer failed 0.000.000.00

incompleteelaborates, no gold match, proof unfinished 0.150.001.00

The shared decision — outcome_for

Every arm calls this first. It reads the columns left to right and returns a row name; the arm then looks up what that row is worth.

if not graded or not wrote_something → no_answer if not type_correct → no_elaborate matches := (BEq+ verdict is True) if not proved and matches → incomplete_faithful if not proved and not matches → incomplete if proved and matches → solved if proved, declares a theorem, not trivial → compiles else → incomplete proved, but of nothing

1 · typecheck — the exploitable baseline

R = 1 if the submission elaborates `sorry` still counts — it is a warning 0 otherwise

Pays for elaboration alone, never reads the gold. Kept as the ablation that shows what a reward with no semantic content buys.

2 · gated — semantics only, flat floor

R = 1.00 if BEq+ matches rows incomplete_faithful + solved 0.25 if exactly one direction proves override on `incomplete` 0.00 otherwise

The flat floor is deliberate. Under GRPO a group with no semantic signal produces zero advantage and contributes no gradient — so nothing below BEq+ can be farmed. It never calls check_own_proof, so proved is always false and solved is unreachable: gated tops out at the BEq+ row.

3 · outcome, as it was — the graded ladder

R = 0.00 / 0.05 / 0.15 / 0.30 / 0.50 rows 1–5, constants 0.85 solved — f was never computed type_correct ← BEq+'s own typecheck (proof sorry'd away) wrote_something ← hardcoded True

4 · outcome, as it ships now

R = 0.00 / 0.05 / 0.15 / 0.30 / 0.50 rows 1–5, unchanged 0.85 + 0.15·f − 0.10·(1 − b) solved type_correct ← check_own_proof (the submission AS WRITTEN) wrote_something ← the submission is non-empty f = faithfulness ∈ [0,1], but signals_from_score passes None → 0 (not wired in-loop at all; offline metric only) b = brevity ∈ [0,1] or None → 1, BEQ_BREVITY_BAND = 0 by default

As shipped this is numerically identical to arm 3 on the solved row: brevity's band defaults to 0, and faithfulness has no in-loop wiring — signals_from_score still passes None, so f = 0. What is not identical is the two signal fixes: a submission whose proof body Lean rejects now scores 0.05 rather than 0.50, and an empty completion scores 0.00 rather than 0.05. Those changed the reward mass distribution substantially — see the subsection below.

The solved row is the only one that is not a constant

R_solved = (V − F) + F·f − B·(1 − b) = (1.00 − 0.15) + 0.15·f − 0.10·(1 − b) = 0.85 when f = 0 and b = 1 ← today: f is None, b is 1

V = 1.00 ceiling · F = 0.15 faithfulness band · B = 0.10 brevity band (shipped at 0). f is paid, so an unknown scores 0; b is deducted, so an unknown scores 1. Both conventions exist so that an unmeasurable signal can never move a score.

Brevity — b ∈ [0,1], deducted

d = log( (L_pred + 60) / (L_gold + 60) ) ← softened log-ratio b = 1 if −log 3 ≤ d ≤ log 1.5 dead band 1 − (d − log 1.5) / (log 4 − log 1.5) if d > log 1.5 too long 1 − (−d − log 3) / (log 10 − log 3) if d < −log 3 too short clamped to [0, 1]

L is the proof body in characters, split at the first bracket-balanced :=. The +60 is not cosmetic: gold bodies run from 1 to ~7,300 chars, and a raw ratio is degenerate at the short end — against a 5-char rfl gold, a good by simp [foo] reads as a 4× overrun. The band is asymmetric (free to 1.5× long, but to 1⁄3 short) because bloat is the target and concision is usually a win.

Faithfulness — f ∈ [0,1], paid

NL proof ──judge──▶ NL blocks ⎫ ⎬──judge──▶ f = score ∈ [0,1] Lean proof ──REPL───▶ FL blocks ⎭ None if either side is empty

FL blocks come from allTactics on the Lean REPL we already hold open. Zero FL blocks returns unknown, never 0 — a term-mode proof has no tactics, and AutoFaith's own empty-branch would return a confident 0.0.

Brevity fires on zero of {{NR_REACH}} reachable rollouts, mean b = 1.0000. Not mis-tuned: 3.5% of all rollouts would be charged, none of the solved ones. Conditioning on a proof that closes already selects for gold-length proofs, so both gates select the same population.

The proof-length reward

disabled on evidence

A length term anchored to the gold: discourage long-winded proofs without letting it be farmed by emitting something degenerately short. Two measurements shaped it.

Gold bodies are tiny and violently skewed — over 18,546 golds: median 67 chars, p90 405, p99 1452, max ~7.3k. Hence the softened ratio.

Never split the body with rfind(":="). 22.4% of golds carry a := inside the proof; for 16.8% that undercounts the body by 40+ chars — worst case 7,406 lost — inventing a phantom one-line reference that marks every honest proof bloated.

A symmetric band penalises good proofs. The first version docked by omega — strictly better than its 61-char gold — 0.012 for being concise. Hence the asymmetry.

Why it is inert, and why that is structural

Conditioning on a proof that actually closes already selects for gold-length proofs. The brevity gate and the correctness gate select the same population, so the term buys nothing — mean b = 1.0000, mean deduction 0.0000 across 182 solved rollouts.

It ships as BEQ_BREVITY_BAND=0. The code stays, and stays correct, because that is a property of the current 128-token response cap — under which three quarters of gold answers do not fit. Raise the cap and long-winded proofs become expressible for the first time. That is when to set the band to 0.10 and A/B it.

NL→FL faithfulness

offline, coverage-limited

The 0.15 band was reserved for a term nothing computed: does the Lean proof carry out the English argument? AutoFaith returns exactly that, in [0,1]. Wired behind one adapter, {{FAITH_N}} rollouts per arm, local judge. Two departures from upstream: FL blocks come from the REPL we already hold open, and zero blocks returns unknown, never zero.

It discriminates, and padding does not fool it

Matched {{FAITH_MATCHED}} vs {{FAITH_MISMATCHED}} for the negative control ({{FAITH_DELTA}}), with mismatched piling up at exactly 0.00. Padding a correct proof with vacuous haves lowers the score by {{FAITH_PAD_DELTA}} — the erosion channel is penalised, not paid.

But the pass is not established, and coverage is fatal

AUC {{FAITH_AUC}}, 95% CI [{{FAITH_AUC_LO}}, {{FAITH_AUC_HI}}] against a 0.80 threshold set before the run. The interval straddles it — at n={{FAITH_NPOS}} vs {{FAITH_NNEG}} that is "needs more data", not a verdict.

Coverage is the harder problem. A term-mode proof (:= rfl) emits no tactics, so AutoFaith's FL side sees nothing — {{FAITH_TERM}}% of the population, verified against Mathlib. Of the rest, the judge fails to return parseable JSON on ~15%. Effective coverage: {{FAITH_COVERAGE}}%.

Left naive this is worse than useless: AutoFaith's _empty() returns a confident 0.0 for zero blocks, docking half of all faithful proofs the entire band. The adapter checks first. But no validity gate tolerates a 60% unknown rate, so this cannot back a band until AutoFaith grows a term-mode path — judging the proof term directly.

One judge finding. LARK-Lab/FormalRx-4b — already served locally for statement-alignment — echoes the prompt instead of answering, even a one-line "return this JSON". The chat template is correct ChatML; it is an SFT specialist and AutoFaith's 12,449-char schema prompt sits far outside its format. Qwen3-4B-Instruct-2507 fixed it: {{FAITH_CALLS}} calls, 0 errors, {{FAITH_SEC}}s each. The two metrics need different models, and only one 4B fits on the card.

Audit: is the reward they attach to sound?

measured

Neither term is worth anything if the ladder underneath is wrong. What follows validates it: what the gate fires on against human labels, what the reward returns for known-answer inputs, where each arm's mass sits, and how the top row moves over training.

What BEq+ fires on

shipped

BEq+ is the gate every arm is built on, and its error rate had never been measured. PAug/ProofNetVerif is 3,752 (gold, prediction) pairs with a human correctness label — the one place that number can come from.

{{N_ALL}} pairs, balanced {{N_POS_ALL}}/{{N_NEG_ALL}} on the human label, one prediction per problem before topping up. A gold-elaboration gate ran first over all 361 problems: {{GATE_OK}} ({{GATE_PCT}}%) of gold statements elaborate against the pinned Mathlib, and the 24 pairs whose gold does not are reported separately — they are guaranteed misses for a version-drift reason that has nothing to do with BEq+.

The reward-hacking surface is small

Zero in {{N_NEG}} human-labelled-wrong pairs. On gated every false positive is a full 1.0 paid for a wrong answer, so this decides whether the reward can be farmed. Rule of three puts the 95% bound at {{FPR_HI}} — small, not proven zero.

Every hit came from one cascade rung

Of {{TP}} true positives, {{RUNG2}} closed at rung 2 (apply <gold> plus solver tactics), {{RUNG3}} at rung 3, {{RUNG4}} at rung 4. Rung 1 (exact?, the only rung setting beql) fired zero times. Rung 4 produced no false positives — but rungs 3–4 still run on every miss, which is most of the cost asymmetry below.

Single-REPL latency by outcomemeanwhy

A miss costs 3× a hit. The cascade is most expensive exactly when it fails, so early training — where misses dominate — is the expensive phase, and the reward gets cheaper as the policy improves.

At n=400 rungs 3 and 4 looked negligible — 6 true positives between them — and truncating the cascade after rung 2 looked like a free latency win. At n={{N_ALL}} they contribute {{RUNG34}} of {{TP}} true positives ({{RUNG34_PCT}}%), and that idea is off the table. The scale-up inverted the conclusion, which is the argument for having run it.

One more thing worth retiring: the gated arm pays 0.25 for a one-direction-only match. That fires on {{ONEDIR_POS}}% of correct pairs and {{ONEDIR_NEG}}% of wrong ones — real but very weak discrimination for a step worth a quarter of the reward.

What the reward returns for answers we already know

2 defects fixed, 1 open

Aggregates over rollouts cannot answer two questions. Ceiling: does the reward pay the top of its ladder for the reference answer itself? Separation: does it order deliberate perturbations the way the table says? A reward can be perfect at the ceiling and flat in the middle, and a flat region contributes zero GRPO advantage.

{{AUDIT_GOLDS}} golds fed back as their own predictions, plus six perturbations each, scored through the real compute_score_* entry points on real Lean — the wiring between table and scorer is the thing under test.

The ceiling is clean

The gold scores {{AUDIT_GOLD_OUTCOME}} on outcome — the maximum without a faithfulness metric — and {{AUDIT_GOLD_GATED}} on gated. BEq+ fires on {{AUDIT_GOLD_BEQ}}%, proved on {{AUDIT_GOLD_PROVED}}%. No hidden ceiling.

Two defects, both fixed

Column 2 was reading the wrong elaboration

signals_from_score took type_correct from BEq+'s own typecheck — which sorries the proof away and so answers "does the statement elaborate", not the table's "lean file.lean exited 0". On the proof-pair task those differ. A submission whose proof body Lean rejects outright (:= by exact?_no_such_tactic) passed column 2, and with a matching statement scored incomplete_faithful — 0.50, identical to an honest sorry. It hit 100% of that perturbation.

Fixed: when a check_own_proof result exists it wins, because it elaborates the submission as written. That case now scores 0.05. BEQ_TYPECHECK_FROM_OWN_PROOF=0 restores the old wiring for comparison — this changes what a run scores, so numbers either side of it are not directly comparable.

Row 1 was unreachable

wrote_something was hardcoded True, so an empty completion scored no_elaborate (0.05) rather than no_answer (0.00) — "wrote nothing" and "wrote broken Lean" were the same reward. Small, and it creates no within-group variance on its own, but the table's floor is 0.00 and it should be reachable. Now wired from the actual submission; an empty answer scores 0.00 on every arm.

One left open, and it is the exploitable one

The two documented hacks — theorem t (n : Nat) : n = n := rfl and theorem t : True := trivial — both land on compiles and collect {{AUDIT_TRIVIAL_OUTCOME}} on the outcome arm, {{AUDIT_TRIVIAL_MATCH}}% agreement with the table. That is double the 0.15 an honest unfinished proof earns, for formalizing nothing.

reward.py already has the guard: row 4 admits a candidate only when statement_is_trivial is not True. The guard cannot fire, because its input is BEq+'s provable_alone — a side effect of cascade rung 3, which only runs when the earlier rungs did not close. Measured over real rollouts, it is known {{GUARD_KNOWN}}% of the time.

The file anticipates exactly this: "a high unknown rate should trip a validity gate instead." No such gate exists. Two ways out, and the choice is a judgement call rather than a bug fix, so I have not made it:

  • Require positive evidence. Admit row 4 only when statement_is_trivial is False. One character, no new Lean calls — but it demotes every honest proved-not-matched rollout from 0.30 to 0.15 too, since their evidence is equally unknown.
  • Measure it directly. Try to close the candidate statement with the solver tactics alone, no reference to the gold. Correct, and costs one extra Lean call per rollout on the rung-4 population only.

Worth noting gated is largely unaffected — it pays {{AUDIT_TRIVIAL_GATED}} for the two hacks. It is outcome, the arm with the graded ladder, that is exposed. And on gated a broken proof body still earns the full 1.0, which is by design (it is a statement metric and never calls check_own_proof) but is worth stating plainly.

The 0-false-positive number is not a safety guarantee

On {{AUDIT_TRIVIAL_SOLVED}} of the trivial submissions BEq+ fired, taking the hack all the way to 0.85. Inspected, the cause is not a cascade error: the gold for that row is theorem ωUnit_coe (p : ℕ) : (ωUnit p : X (q p)) = ω := rfl — itself closed by rfl, so a trivial theorem genuinely is equivalent to it under the metric.

Which is the point. The calibration above measured BEq+ against naturally occurring wrong answers and found zero false positives in 187. Against a deliberately adversarial input the rate is several percent — and a policy optimising this reward is an adversarial input generator by construction. Read the 0/187 as "the metric is not accidentally loose", never as "the metric cannot be gamed".

And one the audit found by accident

The single gold that could not reach solved ({{AUDIT_GOLD_MATCH}}% agreement, not 100) turned out not to be a bad gold. Its context ends open scoped Classical in — a modifier that applies to the next declaration. split_header_and_theorem cuts between them, so the header is elaborated as one command and the theorem as another, and the theorem loses Classical. Its proof uses Classical.by_contradiction, so it fails.

{{DANGLING_PCT}}% of the 760-row val slice ends in such a modifier ({{DANGLING_OPEN}}× open … in, {{DANGLING_VAR}}× variable … in, {{DANGLING_INC}}× include … in). Every one is scored in a context missing something the declaration was written to have — gold and prediction alike. That is a systematic cap on typecheck_rate and on everything downstream of it, and it is invisible in any aggregate because it looks exactly like the model being wrong.

The fix is contained — keep trailing … in lines with the theorem rather than the header — but it changes every BEq+ verdict in the repo, so it is not a change to make quietly.

Where each reward's mass actually sits

the fix has a cost

Calibration says whether a reward is right, not whether it carries signal. Under GRPO the advantage is reward minus group mean, so a rollout at the same value as its group contributes nothing. A reward can be perfectly calibrated and nearly useless.

One fixed policy, {{RATES_N}} rollouts, all three rewards — so any difference between rows is the reward, not the model.

Fixing column 2 collapsed the graded ladder

The outcome arm exists because it pays a graded reward below BEq+ — that is the whole stated reason to run it against gated, whose flat floor deliberately gives up within-group gradient. Before the fix it used four distinct values with {{RATES_PRE_MODAL}}% in the largest. After, it uses two, with {{RATES_POST_MODAL}}% at a single value — the same shape as the typecheck arm it is supposed to be an improvement on.

The cause is that column 2 conflates two genuinely different states: Lean rejects the submission outright, and the statement is fine but the proof body is broken. The old wiring sent the second to 0.50, indistinguishable from an honest sorry — too generous. The new one sends it to 0.05, indistinguishable from unparseable prose — too harsh. {{RATES_MOVED}}% of the benchmark set moved the whole distance between those two.

Neither is right, and the answer is not a wiring choice: it is a missing row. A matched statement with a failed proof attempt is real partial progress and belongs between incomplete (0.15) and incomplete_faithful (0.50). That is a change to the table — the file calls the table the specification — so it is not one to make quietly. Until then, BEQ_TYPECHECK_FROM_OWN_PROOF=0 buys back the graded signal at the cost of restoring the mis-calibration.

Two smaller things the same view shows. gated is the best-conditioned of the three here — {{RATES_GATED_TOP}}% at 1.00 against {{RATES_GATED_BOT}}% at 0.00 is close to the even split that maximises within-group variance — and its 0.25 one-direction step carries {{RATES_GATED_MID}}% of the mass, consistent with the weak discrimination measured against the human labels. And typecheck, the deliberately exploitable baseline, now has the same two-value shape as the shipped outcome arm, which is the clearest possible statement of what the fix cost.

The top of the ladder, over training

flat

With proved measurable, the obvious question is what it does across a run. Nine checkpoints × three arms, n=250 each.

Across 90 steps SOLVED moves +0.000 (gated), +0.012 (outcome) and +0.032 (typecheck). Whatever RL contributes on this task happens before step 10 and then plateaus — so the earlier reading that the arms were "flat on the reported metrics but separated on proved" only holds at a single checkpoint, not as a trend.

The uncomfortable detail is which arm moves most. typecheck — the deliberately exploitable baseline, the one that pays 1.0 for anything that elaborates — has the largest SOLVED gain while its BEq+ rate falls. That is the shape of a policy getting better at closing proofs and no better at formalising the right theorem.

Proof-trajectory alignment

offline only

faithful_score.py rebuilds each tactic state as a standalone theorem and BEq+'s every checkpoint pair. Three things changed before it could be used.

It is not the metric it was slotted against. proof_follows_argument is NL→FL; this is FL↔FL structure against a reference Lean proof and never reads English. Renamed proof_follows_reference; the NL→FL slot stays None.

The raw DP total is monotone in checkpoint count. The candidate picks its own checkpoints and the DP maximises over alignments, so padding buys score — the erosion channel, mechanically incentivised. F1 over the two trajectories removes it.

Pantograph is not needed. lean_interact — already a dependency — returns the same goal-before-tactic states from Command(…, all_tactics=True). That drops a second Lean driver, the async requirement, and the need to write the proof into a built Lean project.

Validated end to end on real Lean: an identical proof scores F1 = 1.00, the same proof padded with three vacuous haves scores 0.57, and a one-shot simp alternative scores 0.67. That last number is the metric's honest cost — a valid different proof is not rewarded.

Out of the loop on cost: 18.9 s for a 2×2 matrix, 60.0 s for 5×2 — ~6 s per cell against a 64-rollout GRPO step. It belongs at checkpoint boundaries on the val split.

The 128-token budget

unresolved

Every RL arm and its SFT init were evaluated at 128 tokens — the --max-new-tokens default, matching run_grpo.sh's MAX_RESPONSE_LENGTH=128. The CoT-distilled comparison used 1536. Across that boundary:

1536-token budget, ~155-token proofs (gold median is 160)  ->  proved 0.000
 128-token budget,  ~53-token proofs                       ->  proved 0.244

That is a striking association and I cannot attribute it to the budget: the two groups differ in training corpus as well, and the checkpoints are not local to re-run. Independent of the confound — 6.1% of gold answers exceed 128 tokens, and 5.3% of eval completions are cut mid-expression at exactly 128 (← mul_assoc, ← mul, Quotient.field_of_injective (Qu). The gold answer is the theorem and proof only — p50 54, p90 115, max 275 Qwen tokens — because the context is supplied in the prompt, so 384 tokens covers every reference answer in the slice.

One eval settles it

Run sft3blocolib_proof at 128 and at 1536 — same checkpoint, two budgets — and measure proved both times. That is the experiment I would run ahead of anything else here, because it decides whether the response cap is protecting the ladder or capping it.
